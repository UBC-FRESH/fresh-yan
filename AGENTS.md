# AGENTS.md

This file is the working contract for AI coding agents in this repository.

## Project purpose

`fresh-yan` hosts the open, reproducible code, data, and results behind the CJFR
manuscript on harvested wood product (HWP) half-life and displacement uncertainty in
forest sector carbon trade-offs (TSA 24, British Columbia). It is built on
[`ws3`](https://github.com/UBC-FRESH/ws3) and
[`libcbm_py`](https://github.com/cat-cfs/libcbm_py).

The durable source of truth is the tracked records under `results/` (regenerated by
tracked CLI entry points) and the analysis scripts that turn them into the manuscript's
figures and tables.

## Non-negotiables

- **Never edit on `main`.** All work happens on a branch (`issue-<n>-<slug>` or
  `phase-<n>-<slug>`), is committed in small steps, pushed, and merged through a pull
  request (squash merge).
- **Records are generated, never hand-edited.** Files under `results/` are produced by
  the CLI; fix the generator or its inputs and regenerate. The same applies to
  `supplementary/` (built by `scripts/build_supplement.py`).
- **Provenance is mandatory.** Every record carries `fy_commit`, `fy_version`, and
  `ws3_version` (plus `libcbm_version` where relevant); `tests/test_records.py` checks
  this.
- **Verify before claiming.** Every number that reaches the manuscript or the
  supplementary must trace to a tracked record and an analysis script. Keep
  `planning/manuscript-handoff.md` up to date.
- **Cross-repo boundaries.** Fixes to `ws3` or `libcbm_py` belong upstream (issues,
  branches, PRs in those repositories) — do not patch them here. The legacy modelling
  repository `msc_walter_yan` is the historical source of the pipeline; new work lands
  here.

## Repository layout

| Path | Purpose |
|------|---------|
| `src/fresh_yan/` | Package: model construction, libCBM utilities, record generation, CLI. |
| `data/` | TSA 24 Woodstock-format model files (inputs). |
| `curves/` | Carbon yield curves (pickles) plugged into the ws3 model. |
| `results/` | Tracked records (no-harvest comparison, base scenario, trade-off and sensitivity grids). |
| `scripts/` | Analysis, figure, table, and supplement builders. |
| `supplementary/` | Curated supplementary pages built from records. |
| `tests/` | Package-backed tests (records provenance, invariants, model smoke tests). |
| `docs/` | Documentation. |
| `planning/` | Plans and manuscript hand-off notes. |
| `CHANGE_LOG.md` | Reverse-chronological project narrative. |
| `ROADMAP.md` | Phase plan and issue map. |

## Branch and issue workflow

- One phase or issue per branch, created from an up-to-date `main`.
- Commit messages cite issue numbers; squash-merge PR subjects end with `(#<PR>)`.
- Record every change set in `CHANGE_LOG.md` immediately after implementation.

## Records and environment

- Regenerate records with the tracked commands documented in
  `results/experiments/REPRODUCIBILITY.md`; keep that page in sync with the commands
  and the validated versions.
- The validated environment is pinned in `pyproject.toml`. Note that `ws3` is pinned
  to the commit carrying the `to_cbm_sit` fix (UBC-FRESH/ws3#155) because the fix
  postdates the current PyPI release.
